# 湖畔慢釣

## 簡介

湖畔慢釣是一款像素風、完全放置型的釣魚遊戲，以手機直式為優先（寬 360–430px）。頁面在前景開著就會自動釣魚，不需要點擊；想玩時可以參與浮標時機小遊戲，不玩也不影響進度。寬度 ≥ 900px 時改為雙欄：左側湖景、右側為分頁內容。

規格依據為 `docs/PRD.md`（最高依據），實作細節見 `docs/DESIGN.md`。文中的數值皆對照 `src/data/gameConfig.ts` 與 `src/data/equipment.ts`。

## 玩法

- **自動釣魚**：頁面在前景時，每次倒數結束結算一次。釣魚間隔為 `Math.max(30, Math.round(90 * (1 - 0.08 * (魚竿等級 - 1))))` 秒，即 Lv1 為 90 秒、Lv6 為 54 秒，最短 30 秒。背景分頁不釣魚。
- **浮標時機小遊戲（可選）**：每次倒數的最後 3 秒是咬鉤時機，浮標抖動，時機條上的指示器來回移動。點擊湖景或按空白鍵即可出手，每回合只算第一次點擊。
  - 成功：額外金幣 = `min(25, ceil(賣價 × 0.2))`
  - 完美：額外金幣 = `min(25, ceil(賣價 × 0.5))`
  - 失手或沒有出手：0，不扣金幣、不損失魚。倒數不會暫停，不點也照常結算。
- **魚的去向**：普通與少見魚捕獲時自動以賣價出售。稀有、史詩、傳說進入魚包的「待處理」，由你決定出售或保留；保留後移到「已保留」，可單隻或全部出售。魚包無數量上限，全部出售需確認。
- **升級**：魚竿、釣線、魚餌各 Lv1–6，金幣不足時等級與金幣都不變，足夠時扣款升一級，Lv6 不可再升。

  | 裝備 | 升到 Lv2 | Lv3 | Lv4 | Lv5 | Lv6 |
  |---|---:|---:|---:|---:|---:|
  | 魚竿 | 100 | 160 | 260 | 410 | 660 |
  | 釣線 | 150 | 240 | 380 | 610 | 980 |
  | 魚餌 | 200 | 320 | 510 | 820 | 1310 |

  - 魚竿：縮短釣魚間隔。
  - 釣線：把普通魚權重的 0% → 10%，按比例移給少見以上已解鎖的稀有度，越稀有的仍然越少。
  - 魚餌：提高鯉科魚群（小鯽魚、鯉魚、鯽魚、彩鯽、銀鯽、金色鯉魚、錦鯉、月光鯉）在同一稀有度內被抽中的權重，倍率 ×1.0 → ×2.0。不改變稀有度機率，也不改變售價。
- **稀有度與保底**：基礎權重為普通 60、少見 25、稀有 11、史詩 3.5、傳說 0.5（合計 100）。未解鎖的稀有度權重為 0，其餘重新正規化。傳說解鎖後，連續未釣到傳說的次數越多，傳說機率越高：0–49 次為 0.5%、50–99 次為 0.75%、100–149 次為 1%、150–199 次為 1.5%、200 次以上為 2%。
- **圖鑑與解鎖**：共 25 種魚，第一次釣到即登錄圖鑑，未發現的顯示為「？？？」。重複魚不增加進度，出售也不刪除圖鑑紀錄。已發現 5 種解鎖少見、10 種解鎖稀有、15 種解鎖史詩、20 種解鎖傳說。圖鑑可依稀有度篩選（全部／各稀有度）。
- **離線收益**：離開後回來，最多計 4 小時，效率 50%，次數依目前的釣魚間隔換算。每一次都完整套用正常規則（含保底、圖鑑與自動出售，稀有以上進待處理）。時鐘倒退不產生收益，時間戳也不會倒退。回來時以非阻斷摘要卡顯示。
- **通知**：稀有以上釣到時顯示非阻斷橫幅，離線摘要與壞檔提示則是卡片。只有覆蓋存檔、重設、全部出售這類不可逆操作會使用確認對話框。
- **設定**：音效與背景音樂各有獨立開關，背景音樂可調音量；另有減少動態效果選項。音樂由 Web Audio 程式合成（chiptune），第一次點擊後才開始，分頁隱藏時暫停。

## 開發

需求：Node.js 20 或更新版本（CI 使用 Node 22），以及 npm。

```bash
npm install
npm run dev      # Vite 開發伺服器
npm test         # Vitest 單元測試（npm run test:watch 為監看模式）
npm run build    # tsc -b 型別檢查後執行 vite build
```

- `art-preview.html` 是開發用的像素美術預覽頁。只在 `npm run dev` 時開啟 `/art-preview.html`，不會進入建置產物。
- `node src/audio/tools/render-check.mjs [輸出資料夾]` 用無頭 Chromium 離線渲染音樂與所有音效，檢查爆音與無聲，並輸出峰值、RMS 與 WAV（預設 `audio-render/`）。需要 `playwright` 套件與 Chromium，路徑預設為 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`，可用 `CHROMIUM_PATH` 覆寫。
- CI（`.github/workflows/lake-fishing.yml`）在 `lake-fishing/` 變更時執行 `npm ci`、`npm test`、`npm run build`。

## 專案結構

- `docs/`：`PRD.md`（規格，最高依據）與 `DESIGN.md`（實作細節）。
- `src/services/`：純遊戲邏輯（釣魚、小遊戲、經濟、圖鑑、離線、存檔驗證與遷移），不依賴 React，亂數與時間皆可注入。
- `src/data/`：魚類定義、裝備數值與集中設定 `gameConfig.ts`。
- `src/types/`：共用型別與存檔版本常數。
- `src/game/`：React 與服務之間的狀態層（store、`useGame`、啟動載入、音訊單例）。
- `src/components/`：React 畫面與元件（湖景、魚包、裝備、圖鑑、設定、時機條、通知、確認對話框）。
- `src/art/`：程式繪製的像素美術（場景、魚、圖示），不依賴 React。
- `src/audio/`：Web Audio 合成的音樂與音效；`tools/` 放離線渲染檢查。
- `src/styles/`：全域樣式（`app.css`）。

## 存檔

- 儲存於瀏覽器 `localStorage`，key 為 `lake-fishing-save`。重要狀態變更後自動保存；前景期間每 30 秒、切到背景時會更新 `lastOfflineSettlementAt`。
- 目前格式為 `saveVersion: 3`，欄位依 PRD §11，並含 `pendingFish`（待處理）與 `fishInventory`（已保留）。
- 遷移：v1 與 v2 會自動升到 v3。v1 的魚 ID `fish_cultrure` 改為 `fish_xenocypris`，普通與少見的庫存以賣價換成金幣。v2 的 `inventory[]` 轉為 `pendingFish`，`lastActiveAt` 轉為 `lastOfflineSettlementAt`，`perfect` 旗標捨棄、不補償。
- 匯出：設定頁可匯出 JSON。匯入前會完整驗證，失敗不覆蓋現有存檔；成功會取代目前進度，需確認。重設需確認，無法復原。
- 讀檔失敗（JSON 壞掉或驗證不過）時，原始字串備份到 `lake-fishing-save-corrupt-<timestamp>`（同一時間重複時加上 `-1`、`-2` 等後綴），接著開新遊戲，並以卡片告知，卡片可複製備份內容。
- 清除瀏覽器資料可能遺失存檔，換瀏覽器或裝置不會同步，建議定期匯出備份。

## 已知限制

- 本機存檔可被竄改，例如直接改寫 localStorage 或調整裝置時間；清除瀏覽器資料也會遺失存檔。
- 尚未部署。
- 目前沒有 PWA 功能，沒有 manifest 或 Service Worker，也不能離線安裝。
