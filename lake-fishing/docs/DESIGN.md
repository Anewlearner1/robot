## 已確認的產品決策

| 項目 | 決定 |

| 依據 | 全面依 PRD v1.0 修正（使用者確認） |

## 遊戲規則

### 釣魚循環（PRD §4）
- 頁面在前景時，倒數結束只結算一次。
- 稀有度權重：普通 60、少見 25、稀有 11、史詩 3.5、傳說 0.5；未解鎖為 0 並重新正規化；釣線與保底調整後再正規化。
- 抽稀有度 → 在該稀有度已解鎖的魚中依「魚種權重」抽一隻（預設權重 1，魚餌會改變目標魚群的權重，見下）。
- 圖鑑解鎖門檻（已發現不同魚種）：少見 5、稀有 10、史詩 15、傳說 20。

### 裝備（PRD §7）
效果與成本全部集中在 `src/data/equipment.ts` / `gameConfig.ts`。
- **釣竿**：間隔依 PRD 公式（Lv1–6 為 90/83/76/68/61/54 秒）。
- **釣線**：把普通魚權重的 0 → 10% 按目前權重比例移到少見以上已解鎖稀有度（維持現行實作）。
- **魚餌**：只加成「指定魚群」在**同一稀有度內**被抽中的權重（Lv1 ×1.0 → Lv6 ×2.0），**不改變任何稀有度機率、不改變售價**。目標魚群為設定參數 `bait.targetFishIds`，預設為鯉科魚群：小鯽魚、鯉魚、鯽魚、彩鯽、銀鯽、金色鯉魚、錦鯉、月光鯉。屬 PRD §17 可調參數。
- 售價一律為魚的 `sellPrice`，沒有乘數。

### 傳說保底（PRD §4）
- 只在傳說已解鎖後生效；非傳說 +1、傳說歸零；未解鎖時不增不減。
- 級距：0–49 為 0.5%、50–99 為 0.75%、100–149 為 1%、150–199 為 1.5%、200+ 為 2%；增加量按比例從其他已解鎖稀有度扣除，總和 100。
- 保底跨裝備更換、重新載入、離線結算保存。

### 出售、待處理與魚包（PRD §6、§10）
- 普通／少見：捕獲時以 `sellPrice` 自動出售。
- 稀有／史詩／傳說：加入 `pendingFish`（同魚種、同來源可合併數量）。玩家可「出售」或「保留」；保留後移入 `fishInventory`（魚種 → 數量）。
- 魚包頁顯示：待處理稀有魚（出售／保留）、已保留的魚（魚名、稀有度、數量、售價、出售 1 隻／全部）。全部賣出需確認。
- 出售需驗證持有數量、增加金幣、更新 `stats.totalFishSold` 與 `stats.totalCoinsEarned`；不影響圖鑑；避免重複出售。

### 浮標時機小遊戲（PRD §9）
- 每次倒數的最後幾秒（`gameConfig.minigame.windowSeconds`，預設 3 秒）是「咬鉤時機」：浮標在湖景上抖動，畫面上出現一條時機條，指示器來回移動，中間有「時機區」與更窄的「完美區」。
- 玩家點擊湖景（或按空白鍵）一次即出手；每回合只算第一次點擊。**不暫停計時、不擋畫面**，不理它就照常結算。
- 結果：完美 / 成功 / 失手 / 未參與。倒數結束時照常結算一次捕獲，並依結果加額外金幣：
  - 額外金幣 = `min(cap, ceil(sellPrice × 比例))`，比例預設成功 0.2、完美 0.5，`cap` = 25（每回合上限）。
  - 失手或未參與：0，不扣金幣、不損失魚。
- 連續完美（`perfectStreak`）可小幅提高「特殊魚」機率：每連續一次，稀有以上已解鎖稀有度的權重 +`streakBonusPerPerfect`（預設 0，屬 PRD §17 待定案參數），上限 `streakBonusMax`。一律在解鎖過濾之後、保底之前套用，不可繞過解鎖、圖鑑或保底。
- 背景、離線期間沒有小遊戲（離線捕獲 `source = "offline"`）。

### 離線收益（PRD §8）
- `elapsedSeconds = max(0, now - lastOfflineSettlementAt)`，上限 14,400 秒；有效次數 `floor(min(elapsed, 14400) / interval × 0.5)`。
- 每次完整套用正常規則（解鎖、裝備、保底、圖鑑、自動出售；稀有以上進待處理，`source = "offline"`）。
- 結算後立即更新時間戳並存檔，重複結算得 0。
- 時鐘倒退：不產生收益，**且不把時間戳往回調**（只在 `now > lastOfflineSettlementAt` 時前進）。
- 前景期間每 30 秒、隱藏分頁時更新 `lastOfflineSettlementAt`。
- 回來時以非阻斷摘要卡顯示「你不在的時候…」。

### 存檔（PRD §11）
- `localStorage` key `lake-fishing-save`，重要狀態變更後自動保存。
- `saveVersion: 3`，欄位對齊 PRD 建議：`saveVersion`、`createdAt`、`lastSavedAt`、`lastOfflineSettlementAt`、`coins`、`equipmentLevels`、`discoveredFishIds`、`fishInventory`、`pendingFish`（含 `quantity`、`source`）、`pity.consecutiveNonLegendary`、`stats.{totalCatches,totalFishSold,totalCoinsEarned}`、`settings.{soundEnabled,reducedMotion}`。
  - 額外欄位：`catchCounts`（圖鑑捕獲數）、`minigame.perfectStreak`、`settings.musicEnabled`、`settings.musicVolume`、`nextPendingId`。
- 遷移：v1 → v3、v2 → v3（v2 的 `inventory[]` 轉為 `pendingFish`，`lastActiveAt` → `lastOfflineSettlementAt`，`perfect` 旗標捨棄、不補償）。
- 匯入前完整驗證；失敗不覆蓋；覆蓋前確認；壞檔先備份到 `lake-fishing-save-corrupt-<timestamp>`，並提供「複製備份內容」讓玩家保存。
- 設定頁提醒：清除瀏覽器資料可能遺失存檔、不會跨瀏覽器／裝置同步、建議定期匯出備份。

### 資料修正
- 魚 ID `fish_cultrure` 改為 `fish_xenocypris`（imageKey `fish-xenocypris`）。v1 存檔遷移時一併轉換。

## 畫面（PRD §10）

底部分頁列：**湖畔 / 魚包 / 裝備 / 圖鑑 / 設定**（≥ 900px 時分頁內容在右欄）

- **湖畔**：金幣、圖鑑進度（已發現／25 與百分比）、倒數與進度條、湖景（角色、水面、浮標）、浮標時機條、最近 5 筆紀錄、非阻斷通知區（稀有魚、離線摘要）。
- **魚包**：待處理稀有魚（出售／保留）＋已保留魚（魚名、稀有度、數量、售價、出售）。
- **裝備**：等級、目前效果、下一級效果、成本；金幣不足顯示「還差 N 金幣」；滿級顯示「已達最高等級」。
- **圖鑑**：25 格、已發現數、完成百分比、稀有度篩選（全部／各稀有度）、未發現剪影「？？？」；詳情顯示售價、介紹、捕獲數。
- **設定**：音效開關、背景音樂開關與音量、減少動態效果、匯出／匯入、重設、存檔提醒、版本。

稀有度顏色：普通 灰白、少見 綠、稀有 藍、史詩 紫、傳說 金。

## 技術約定

- 專案位於 repo 的 `lake-fishing/`，獨立的 Vite + React 19 + TypeScript + Vitest 專案。
- 遊戲邏輯一律是 `src/services/` 裡的純函式（可注入 `rng` 與 `now`），並有單元測試。UI 不得自行計算遊戲數值，顯示文字中的數字一律來自服務層或設定檔。
- 像素美術放在 `src/art/`，音訊放在 `src/audio/`，不依賴 React。
- 不使用外部圖片、字型或音檔；不需要網路。
- 每個開發階段依 PRD §16 格式回報，不得捏造測試結果。
